## 1. 站点概况

| 项目 | 当前值 |
| --- | --- |
| 站点标题 | MistField |
| 副标题 | wander |
| 站点地址 | `https://mistfield.cuteleaf.cn` |
| 站点语言 | `zh_CN`（简体中文） |
| 主题模板 | Firefly v6.15.8（基于 Astro 7.2.0 + Svelte 5 + Tailwind CSS 4） |
| 壁纸模式 | `"none"` 纯色背景（黑白简约风格，参考 Firefly-Mod） |
| 侧边栏 | **已关闭**（`sidebarLayoutConfig.enable: false`） |
| 评论系统 | **未启用**（`commentConfig.type: "none"`） |
| 页面过渡 | Swup（`@swup/astro`），已配置 `persistTags` 保留页面级样式表 |

本站与原版 Firefly 演示站的主要差异：

- 壁纸模式改为 `"none"`（纯色背景），横幅文字、水波纹等壁纸相关配置保留但仅在切回壁纸模式时生效；
- 侧边栏整体关闭，资料卡 / 公告 / 分类 / 标签等侧边栏组件暂不显示（移动端底部组件同理）；
- 打赏页面关闭（`pages.sponsor: false`），打赏配置保留；
- 导航栏顶层「链接」菜单（GitHub / Gitee / QQ交流群 / Firefly文档）**暂时注释停用**，需要时取消注释即可恢复；
- 追番页为本站版本的 `/anime/`（Bilibili + TMDB），而非原版的 `/bilibili/` 与 `/myanimelist/` 双页面。

## 2. 快速开始

### 环境要求

- Node.js **22.0** 或更高版本
- pnpm 包管理器（锁定版本 `pnpm@9.14.4`，`preinstall` 脚本强制只允许 pnpm）
- Git

### 常用命令

| 命令 | 说明 |
| --- | --- |
| `pnpm dev` / `pnpm start` | 启动本地开发服务器（端口 4321） |
| `pnpm check` | 运行 Astro 诊断 |
| `pnpm type-check` | TypeScript 类型检查（`tsc --noEmit --isolatedDeclarations`） |
| `pnpm format` | Biome 格式化 `src` 与 `scripts` |
| `pnpm lint` | Biome 检查并安全修复 |
| `pnpm build` | 生产构建（见下方构建流水线） |
| `pnpm preview` | 本地预览生产构建产物 |
| `pnpm new-post` | 交互式创建新文章（`scripts/new-post.js`） |
| `pnpm new-dynamic "内容"` | 快速发布一条动态（别名 `pnpm new-d`） |
| `pnpm lqips` | 单独重新生成图片 LQIP 占位图 |

`pnpm build` 的完整流水线（按顺序执行）：

1. `scripts/generate-lqips.ts` — 生成图片低质量占位图（LQIP）
2. `scripts/generate-vndb-covers.ts` — 下载并压缩 VNDB 封面（满足条件时）
3. `astro build` — Astro 构建
4. `scripts/prune-pio-assets.ts` — 裁剪未启用的看板娘模型资源
5. `scripts/subset-fonts.ts` — 本地字体子集化
6. `scripts/minify-inline-scripts.ts` — 压缩内联脚本
7. `pagefind --site dist` — 生成 Pagefind 全文搜索索引

## 3. 站点基础配置（siteConfig）

文件：`src/config/siteConfig.ts`

### 基础信息（本站当前值）

```ts
title: "MistField",
subtitle: "wander",
site_url: "https://mistfield.cuteleaf.cn",
lang: "zh_CN",   // 文件顶部 SITE_LANG 常量定义
timezone: "Asia/Shanghai",
siteStartDate: "2026-08-13",   // 用于统计"运行天数"
```

- `description` / `keywords` 用于 `<meta>` 标签与 SEO，当前仍沿用主题默认文案，**建议替换为自己的站点描述**。
- `lang` 可用环境变量 `PUBLIC_SITE_LANG` 覆盖（支持 `en` / `zh_cn` / `zh_tw` / `ja` / `ru` / `ko`，大小写不敏感）。

### 主题色

```ts
themeColor: {
	hue: 165,             // 色相 0-360：红 0 / 青 200 / 蓝绿 250 / 粉 345
	defaultMode: "system", // "light" | "dark" | "system" 跟随系统
},
```

### 外观与布局（本站当前值）

| 配置 | 值 | 说明 |
| --- | --- | --- |
| `pageWidth` | `100` | 页面整体最大宽度（rem） |
| `card.border` | `false` | 卡片边框与阴影（本站关闭） |
| `card.followTheme` | `false` | 卡片浅色模式下是否跟随主题色 |
| `categoryBar` | `true` | 首页/归档页顶部分类快捷导航 |
| `categoryStyle` | `"rectangle"` | 分类按钮形状：`pill` 胶囊 / `rectangle` 矩形 |
| `tagStyle` | `"pill"` | 标签样式：`pill` 中性灰底 / `rectangle` 主题色底 |
| `foldArticle` | `true` | 归档页折叠非最新年份文章 |

### Favicon 与导航栏 Logo

```ts
favicon: [{ src: "/favicon/firefly-32.png" }],

navbar: {
	logo: {
		type: "image",
		value: "assets/images/logo/firefly-light.png",      // src 目录，自动优化
		valueDark: "assets/images/logo/firefly-dark.png",   // 暗色模式换图
		alt: "🍀",
	},
	title: "MistField",
	widthFull: false,
```

Logo 支持四种写法：`icon`（Iconify 图标，自动跟随亮暗色）、`image` + `/` 开头（public 目录不优化）、`image` 不带 `/`（src 目录自动优化，**推荐**）、`url`（网络图片）。`valueDark` 仅对 `image` / `url` 生效。

### 图像优化

```ts
imageOptimization: {
	formats: "webp",       // "avif" | "webp" | "both"
	quality: 85,           // 推荐 70-85
	noReferrerDomains: ["*.hdslb.com", "*.bilibili.com"],  // 防盗链处理
},
```

`noReferrerDomains` 中的域名（支持 `*` 通配符）图片会自动加 `referrerpolicy="no-referrer"`，解决 B 站图床等 403 防盗链问题。仅对 `http(s)://` 外链图片生效。

## 4. 导航栏

文件：`src/config/navBarConfig.ts`。导航栏由 `getDynamicNavBarConfig()` 按顺序动态生成，桌面端与移动端共用同一份数据。

### 本站当前菜单结构

```
主页
文章：文章列表 / 归档 / 分类 / 标签
社交：友链 / 留言
我的：动态 / 相册 / 追番 / VNDB / 番组计划 / 书签导航 / 音乐可视化
关于：打赏 / 关于我
（链接：GitHub / Gitee / QQ交流群 / Firefly文档 —— 已注释停用）
```

> 顶层「链接」菜单整块处于注释状态（暂时不用）。恢复方法：打开 `navBarConfig.ts`，找到「自定义导航栏链接（暂时不用…）」注释块取消注释即可。

### 链接预设（LinkPresets）

内置预设：`Home` `PostList` `Dynamic` `Archive` `Categories` `Tags` `Friends` `Sponsor` `Guestbook` `About` `Bangumi` `VNDB` `Gallery` `Anime` `Booknav` `Music`。可直接改它们的 `name` / `icon` / `url`。

自定义链接属性：

| 属性 | 说明 |
| --- | --- |
| `name` | 链接名称（改过默认值后不再参与 i18n 自动翻译） |
| `url` | 链接地址 |
| `icon` | Iconify 图标名 |
| `external` | 外链在新标签页打开 |
| `children` | 子菜单，支持嵌套 |
| `pageKey` | 对应 `siteConfig.pages` 的键，页面关闭时链接自动隐藏 |

### 动态隐藏规则

- `pageKey` 对应页面关闭 → 链接隐藏；
- 父菜单子项全部隐藏 → 父菜单隐藏；
- 父菜单只剩一个子项 → 直接展示该子项。
- 例：本站 `pages.sponsor: false`，所以「关于」菜单里的打赏入口不显示，「关于」组只剩「关于我」时会自动去掉父级包裹。

### 搜索

```ts
export const navBarSearchConfig: NavBarSearchConfig = {
	method: NavBarSearchMethod.PageFind,
};
```

搜索索引在 `pnpm build` 最后一步由 Pagefind 生成，因此**开发模式下搜索可能没有数据，属正常现象**。

预装图标集：`fa7-brands`、`fa7-regular`、`fa7-solid`、`material-symbols`、`simple-icons`、`mingcute`。需要其他图标集：`pnpm add @iconify-json/<图标集名>`，图标名可在 <https://icones.js.org/> 查询。

## 5. 侧边栏与小组件

文件：`src/config/sidebarConfig.ts`。

> **本站现状：`enable: false`，侧边栏整体关闭。** 配置仍然保留，把 `enable` 改回 `true` 即可恢复下述布局。

### 布局配置

| 属性 | 本站值 | 说明 |
| --- | --- | --- |
| `enable` | `false` | 侧边栏总开关 |
| `position` | `"both"` | `left` / `right` / `both` 双侧 |
| `tabletSidebar` | `"left"` | 平板端（769–1279px）显示哪侧 |
| `hideSidebarOnPostPage` | `false` | 文章详情页是否隐藏侧边栏 |
| `showBothSidebarsOnPostPage` | `true` | 单侧栏时文章页是否补出对侧栏 |

### 本站预置的组件编排（启用侧边栏后生效）

左侧栏（`leftComponents`）：

1. `profile` 资料卡（top）
2. `announcement` 公告（top）
3. `music` 音乐播放器（sticky）
4. `categories` 分类（sticky，超过 5 个自动折叠）
5. `tags` 标签云（sticky，超过 10 个自动折叠）

右侧栏（`rightComponents`）：

1. `dynamic` 最新动态（top，`limit: 2`）
2. `stats` 站点统计（top，仅非文章页）
3. `siteInfo` 站点信息（top）
4. `calendar` 日历 + 年度热力图（sticky，仅非文章页）
5. `sidebarToc` 文章目录（sticky，仅文章页）
6. `advertisement` 广告位 ×2（均为 `enable: false`，见第 15.9 节）

移动端底部（`mobileBottomComponents`，<768px）：profile / announcement / categories / tags / dynamic / stats / siteInfo。移动端配置**独立于左右侧栏**，不写 `position`，需要单独维护。

组件通用属性：`type`、`enable`、`position`（`top` 固定 / `sticky` 粘性）、`showOnPostPage`、`hideOnNonPostPage`、`showTitle`、`specificConfig`。渲染顺序即数组顺序，但 `top` 组件优先于 `sticky`。

## 6. 个人资料

文件：`src/config/profileConfig.ts`（本站当前值）：

```ts
avatar: "assets/images/avatar.avif",  // src 目录，自动优化（推荐）
name: "Firefly",
bio: "Hello, I'm a whale.",
links: [],                            // 社交链接目前为空
```

社交链接示例：

```ts
links: [
	{ name: "GitHub", icon: "fa7-brands:github", url: "https://github.com/xxx", showName: false },
	{ name: "Email", icon: "fa7-solid:envelope", url: "mailto:you@example.com" },
```

## 7. 公告

文件：`src/config/announcementConfig.ts`。本站包含两部分：

### 侧边栏公告

```ts
title: "公告",
content: "欢迎来到我的博客！这是一则示例公告。",
closable: true,
link: { enable: true, text: "了解更多", url: "/about/", external: false },
```

### 首页跑马灯公告（`items`）

### 已定义字体（fontsList）

| --- | --- | --- |

## 11. 编写文章

### 存放与创建

- 文章目录：`src/content/posts/`，支持 `.md` / `.mdx`，可建子目录组织文章与配套图片；
- 快捷创建：`pnpm new-post`（交互式）；
- 本站现有的示例文章可作参考：`markdown-tutorial.md`（Markdown 教程）、`code-examples.md`（代码块）、`katex-math-example.md`（公式）、`markdown-mermaid.md`、`markdown-plantuml.md`、`markdown-extended.md`（扩展语法）、`mdx-example.mdx`（MDX）、`encrypted-demo.md`（加密文章）、`video.md`（视频嵌入）、`guide/` 子目录示例（含同目录封面图）。

### Front-matter

```yaml
---
title: 文章标题
published: 2026-08-17        # 必填
updated: 2026-08-17          # 可选，默认等于 published
description: 文章简介，显示在列表卡片上
image: ./cover.jpg           # 封面：相对路径 / /assets/... / https://... / "api"
tags: [标签1, 标签2]
category: 分类名
draft: false                 # true 则不发布
pinned: false                # true 置顶
slug: custom-url             # 自定义 URL（默认用文件名）
author: 作者名
comment: true                # 单篇关闭评论用 false
licenseName: ""              # 覆盖全局许可证
licenseUrl: ""
sourceLink: ""               # 转载来源
password: ""                 # 文章加密（见下文）
passwordHint: ""             # 密码提示
---
```

Slug 建议：英文 + 连字符（`my-first-post`），发布后不要随意更改。

### 文章加密

Front-matter 加 `password: "xxx"` 即启用。构建时用 AES-256-GCM 加密，页面源码无明文；访客输入密码后由浏览器 Web Crypto 本地解密。

- 加密范围：正文、打赏/分享块、许可证块；标题、元数据、封面**不加密**；评论区隐藏；RSS 仅输出标题和描述；
- 密码缓存在 `sessionStorage`，关闭浏览器失效；
- 密文公开在源码中，请使用足够强的密码；
- 示例文章：`src/content/posts/encrypted-demo.md`。

### 数学公式（KaTeX）

行内 `$e^{i\pi}+1=0$`；块级 `$$...$$` 居中；支持矩阵、求和、极限、化学方程式（`\ce{...}`）。

### 提醒框（Admonitions）

本站主题为 `github` 风格：

```markdown
> [!NOTE] 提示
> [!TIP] 建议
> [!IMPORTANT] 重要
> [!WARNING] 警告
> [!CAUTION] 注意
```

Docusaurus 风格 `:::note ... :::` 也可用。`!!!` / `???`（Python-Markdown）语法需将主题切换为 `obsidian` 并开启 `enablePythonMarkdownAdmonitions`。

### 其他扩展语法

- GitHub 仓库卡片：`::github{repo="CuteLeaf/Firefly"}`；
- 剧透文本：`:spoiler[被隐藏的内容]`；
- 嵌入视频：直接粘贴 B 站 / YouTube 的 `<iframe>` 代码（参考 `video.md`）；
- Wiki Link：`guide/firefly-wiki-link.md` 有说明；
- MDX：可 `import` 组件、使用 JS 表达式，无特殊需求优先用普通 Markdown。

## 19. 部署

本站仓库同时带了三套部署配置，实际使用时选择其一。`astro.config.mjs` 中 `site` 已绑定 `siteConfig.site_url`，`base: "/"`、`trailingSlash: "always"`。

### 19.1 GitHub Pages（`.github/workflows/deploy.yml`）

仓库已包含完整工作流：推送 `master` 分支触发，Node 22 + pnpm 9.14.4，`pnpm install --no-frozen-lockfile` → `pnpm run build` → 生成 `.nojekyll` → `actions/upload-pages-artifact` + `actions/deploy-pages`。使用前提：仓库 Settings → Pages → Source 选择 **GitHub Actions**。若部署到 `https://<用户名>.github.io/<仓库名>/` 需要在 `astro.config.mjs` 设置 `base`；自定义域名则不需要。

### 19.2 Vercel（`vercel.json`）

仓库已含配置：`framework: astro`、`buildCommand: pnpm build`、`outputDirectory: dist`，并额外声明了：

- 全站安全响应头：`X-Content-Type-Options: nosniff`、`X-Frame-Options: SAMEORIGIN`、`X-XSS-Protection`、`Referrer-Policy: strict-origin-when-cross-origin`；
- `/_astro/*` 静态资源一年不可变缓存（`max-age=31536000, immutable`）。

控制台导入仓库即可自动识别；记得在 Settings → General 把 Node.js Version 设为 `22.x`。

### 19.3 Cloudflare（`wrangler.jsonc`）

```jsonc
{
	"name": "firefly",
	"compatibility_date": "2026-08-13",
	"compatibility_flags": ["nodejs_compat"],
	"assets": { "directory": "./dist" }
}
```

- **Pages 部署**（纯静态，推荐）：构建命令 `pnpm build`，输出目录 `dist`，无需适配器；
- **Workers SSR 部署**：需要设置环境变量 `CF_WORKERS=true` 才会启用 `@astrojs/cloudflare` 适配器，其他平台不受影响；
- 手动部署：`npx wrangler deploy`。

### 19.4 自有服务器

本地 `pnpm build` 后把 `dist/` 整目录上传到 Nginx/Apache 即可。

### 19.5 构建期环境变量汇总

| 变量 | 说明 |
| --- | --- |
| `NODE_VERSION` | Node 版本，需 ≥ 22 |
| `PUBLIC_SITE_LANG` | 覆盖站点语言（en / zh_cn / zh_tw / ja / ru / ko） |
| `PUBLIC_PAGES_<KEY>` | 覆盖任意页面开关，如 `PUBLIC_PAGES_GALLERY=false` |
| `PUBLIC_DISPLAY_SETTINGS` | 开启显示设置面板 |
| `CF_WORKERS` | 仅 Cloudflare Workers SSR 需要 |
| `FIREFLY_BUILD_PLATFORM` | 自定义站点信息组件显示的构建平台名 |

`PUBLIC_` 前缀变量会注入浏览器端代码，只用于开关类配置，**不要放密钥**。

### 19.6 部署注意事项

- 每次推送自动触发重新构建；Bangumi `dynamic` 模式数据实时更新，`static` 数据（VNDB 等）需重新构建；
- 真实网络下切页依赖 swup head-plugin 的 `persistTags` 配置防止页面级 CSS 提前移除（见 15.8），部署后如遇切页样式闪烁请优先检查该配置是否被回退。

## 20. 更新主题模板

### 方法一：Git 合并（推荐）

```bash
git remote add upstream https://github.com/CuteLeaf/Firefly.git   # 仅首次
git fetch upstream
git merge upstream/master
# 解决冲突（通常集中在 src/config/ 与 astro.config.mjs）
git add . && git commit -m "merge: update Firefly theme"
```

为减少冲突：尽量只改 `src/config/`、`src/content/`、`public/`，不动主题核心文件。本站已有的本地化改动（合并时需留意）：

- `astro.config.mjs`：swup `updateHead.persistTags`；
- `src/config/backgroundWallpaper.ts`：`mode: "none"`；
- `src/config/sidebarConfig.ts`：`enable: false`；
- `src/config/siteConfig.ts`：站点信息与页面开关；
- `src/config/navBarConfig.ts`：注释掉的「链接」菜单；
- `src/components/features/music-visualizer/`：封面闪烁修复。

### 方法二：手动覆盖

备份 `src/config/`、`src/content/`、`public/` → 下载新版 → 还原备份 → `pnpm install` → `pnpm dev` 检查报错。

### 更新后检查清单

1. `pnpm type-check`（类型报错通常意味着配置新增必填字段）；
2. `pnpm check`；
3. `pnpm dev` 本地预览各页面；
4. `pnpm build` 完整构建（含字体子集化、LQIP、Pagefind）；
5. 查看上游 commit 记录确认破坏性变更。
